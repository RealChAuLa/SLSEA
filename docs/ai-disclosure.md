## Assumptions and contract decisions

- Node 24 LTS, ESM throughout, and a planned Prisma major 7 pin. Prisma and its
  adapter/client are installed only in I1. Official Prisma 7 documentation requires
  ESM and a driver adapter; exact I1 package versions remain to be pinned.
- I0 config validates only `NODE_ENV`, `PORT`, and `CORS_ORIGINS`. The example lists
  every blueprint variable, with secrets blank and future settings unused.
- `/docs` is the blueprint's required HTML exception to the JSON-only rule.
  Negotiation uses HTML for docs and JSON elsewhere.
- Oversized JSON maps to `400 VALIDATION_FAILED` because §4.7 defines no 413 code.
  Compressed JSON is disabled and unsupported charset/encoding maps to 415.
- Request IDs are generated by the server rather than echoing untrusted input.
  Logs use matched route templates and omit error messages to prevent secret leaks;
  fault type and stack source locations remain available on the server.
- HEAD is explicitly rejected on GET-only paths, consistent with I0's `Allow: GET`
  requirement. Configured-origin CORS preflights are a middleware-level 204.
- Strong representation ETags satisfy §4.3; conditional evaluation remains I3.
  Sending serialized payloads with `end` prevents Express's implicit 304 behavior.
- Vercel is configured as an explicit Node function with catch-all rewrites,
  default app export, and included generated JSON. `framework: null` keeps the
  specified `api/index.js` entry consistent despite automatic Express detection.
- Remote CI/deployment cannot be claimed green from local tests; the workflow
  must run after the owner pushes. I0 has no database calls.
